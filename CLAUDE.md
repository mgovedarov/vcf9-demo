# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A VMware Orchestrator (vRO / VCF Automation) content export in the on-disk layout used by the VS Code / IDE "o11n" sync tooling. There is no build system, package.json, linter, or test suite — the files are the XML and JSON that Orchestrator imports and exports. Changes are validated by syncing to a live Orchestrator, not locally.

## Layout

- `Workflows/<Folder>/<Workflow Name>/workflow.xml` — workflow definition (`ns2:workflow`, with `id` GUID, inputs/outputs, `workflow-item` nodes and their embedded scripts).
- `Workflows/<Folder>/<Workflow Name>/forms/_.json` — the workflow's custom input form (schema + layout). An empty form is `{"schema":{},"layout":{"pages":[]},"itemId":""}`.
- `Actions/<category path>/<name>.xml` — one `dunes-script-module` per action; the category is the dotted form of the directory path (e.g. `com/vmware/vra/xaas` → `com.vmware.vra.xaas`).
- `Configurations/` — configuration elements (e.g. `web-root/test1.xml`).
- `Packages/<name>.xml` — package manifest: `<elm>` `dunes://` references to the actions/workflows it contains, plus `used-plugin` entries.
- `.o11n/links/` — sync-tool metadata mapping each object GUID (and `<GUID>_input_form` for forms) to its local file path. Tracked in git but tool-managed; don't edit by hand. Git history shows it being deleted/regenerated by the tool ("Delete .o11n directory").

## Working conventions

- Every workflow/action/config is identified by its GUID (`id` attribute). Keep the GUID stable when editing; a new object needs a new GUID and, for the sync tool, a matching `.o11n/links` entry (let the tool create it).
- Workflow folder names differ in case (`Workflows/Test/` vs `Workflows/test/`) — these are separate Orchestrator categories; preserve the exact path when referencing or moving items.
- Scripts inside `workflow.xml` and actions are ES5-era Orchestrator JavaScript (Rhino), not modern JS/TS — no `let`/`const`, arrow functions, or template literals.
- Adding a new action or workflow to a package requires an `<elm>` entry in the matching `Packages/*.xml`.
- Keep hostnames, credentials, and other environment-specific values out of these files, especially in `Configurations/`.
- The `vrbt-typescript` skill covers TypeScript-based vRO projects; this repo is the plain XML export format, not a vRBT Maven project.
